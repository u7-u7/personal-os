# 自带日历优先与 AI 日程完整性

用户在 2026-10-29 明确先使用 PersonalOS 自带日历，Google Calendar 无需接入，继续自主开发和验证。Google 保留为可选能力，不再作为当前使用和候选版的强制凭据前提；授权数据面状态仍明确未验收。

本次沿用已有 SDD 与 Record 服务，风险评分 15（应用30、API0、数据0、条件30，四项均权）。不新增表、索引、迁移或依赖。相比复制独立 SQL，复用已有 list_events 的 owner / soft-delete / 半开时间窗 / start_at+id 排序，避免不同入口产生日期判断差异。

实施：Agent 工具读取当前时刻起7天的全部本地日程，简报读取当前时刻起24小时的全部本地日程；本地和已连接的外部日历共用同一对时间戳。上述为滚动窗口，不改变为用户时区的自然日。Dashboard 取未来7天最早4条，与现有预览容量一致。HTTP /events 仍限制每页最多200条，内部有窗口查询可不设行数上限。

Web 复用已缓存 Settings 的服务端连接快照（按owner/provider/connected/deleted过滤后取一条，只返回id/version），不以截断的integrations列表缺席判断连接。未连接 Google 时不发外部事件请求，显示可选说明与使用本地日历入口。权限/状态读取失败及已连接的外部调用失败继续显示错误和重试，不将失败当作空闲。首页日历空态同样区分加载、错误与成功空数据。

验证：运行现有后端、Web静态检查与E2E，不新增测试用例；独立QA账号和真实PostgreSQL复核旧创建事件、>100日程、进行中/已结束/远期边界、软删除和owner隔离；用真实授权模型检查只读工具选用及简报来源。UI验收本地默认、未连接Google说明、恢复本地及移动端。外部Google不调用、不宣称完成授权验收。

边界：完整时间窗可能增大模型上下文，高密度日程下仍受真实模型上下文/超时限制，失败明确返回。Google分页和OAuth擦除并发风险保留为非当前优先待办。任务/记忆列表的独立容量问题不混入此修复。任何无法完成的真实验收单列，不用模拟回答替代。
